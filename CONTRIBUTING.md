# Contributing

First: thank you for reading this far. This method came out of real serials and real
mistakes — every law here was paid for. If you write with it, you're extending the
experiment, and your findings are welcome.

## Ways to contribute

| You have… | Do this |
|---|---|
| A question about applying the method | open an issue with the *method question* template |
| A new check, gate, or audit idea | open an issue, label `gate-idea` |
| A correction to a doc or template | PR (see rules below), label `template-feedback` |
| A serial you built with this method | start a Discussion, label `show-and-tell` — numbers welcome |
| A case study with receipts | Discussions — the best ones get cited in `docs/04` |

## House rules (they will look familiar)

1. **Add-only spirit.** Corrections supersede, they don't silently rewrite history.
2. **Claims carry receipts.** "This law works" is a wish; "this law caught X in serial Y" is a fact.
3. **A law without a check is a wish.** New laws must ship with a way to enforce them.
4. **Be kind.** Fan fiction is love made public. Treat other people's serials accordingly.

## PR checklist

- [ ] The docs still build as plain Markdown (no broken relative links)
- [ ] `python3 examples/minigate.py --selftest` still prints `SELFTEST PASS`
- [ ] New claims carry their receipts (serial, chapter, date)

---

*This guide is fandom-neutral. Your fandom's rules for fan work outrank anything here.*
